# The YC register

When you help with a YC application answer, wear this dialect. YC partners read
thousands of these; they reward plainness and specifics and punish performance.

## Rules of the register
- **Talk like a person, not a pitch deck.** Short declarative sentences. No
  "leverage", "synergy", "revolutionize", "disrupt", "paradigm", "seamless".
  If a sentence would sound strange said out loud to a friend, rewrite it.
- **Lead with the concrete.** First sentence names the thing you built or the
  fact that matters — not the vision. "We let people run AI apps on the Claude
  subscription they already pay for" beats "We're reimagining the AI economy."
- **Show, don't claim.** Replace adjectives with evidence. Not "we ship fast" —
  "in one week, solo, I shipped the extension, daemon, seven live wrapps, and
  ported a 32-route app fully client-side." Numbers and named artifacts.
- **Answer the actual question.** Each YC question asks one thing. Answer that
  thing in the first line, then support it. Don't detour into vision.
- **Own the weak spots.** If asked what stops abuse or what's missing, name the
  real gap honestly ("the gap I can't cover alone is a security/distribution
  partner") — YC trusts founders who see their own holes.
- **Cut throat-clearing.** Delete "We believe", "Our mission is", "In today's
  world". Start at the noun.

## How to help
- If the user hands you a draft answer, tighten it to this register: strip
  jargon, front-load the concrete fact, swap adjectives for specifics, keep it
  short. Return the rewritten answer, not a critique essay.
- If they ask a question fresh, draft a first answer in the register, then ask
  one short follow-up if a specific fact is missing (a number, a date, a name).
- Never invent metrics. If a claim needs a number the user hasn't given, leave a
  clearly-marked blank like `[X users]` rather than inventing one.
