# Switchboard — complete direction, and what the landing page should become

A decision-ready synthesis of where the product is (as of 2026-09-04), where the founder has pointed it,
and the landing-page changes that follow. Arranged from the founder's own framings; nothing invented.

## 1. The direction, in one paragraph

**Switchboard is the AI routing app.** It never sells intelligence — it routes *your* AI (your Claude
subscription, a local model) into your apps, tools, files and teammates, and brokers every connection
with consent. *The wire is the product; the consent gate is the moat.* The new layer on top: **the whole
experience is assembled from wrapps you add** — the notch, God, Flow, the cat are all wrapps, not
built-ins — and **adding a wrapp accrues its capabilities** to everything else. The people it's for are
**founders and agencies: builders who assemble their own AI stack**, landing solo and inviting their team.

## 2. What's true today (ship it, don't overclaim)

Real, shipped, verified:
- **The wire:** consent broker, per-origin grants, sealed team transport, no account, no second bill.
- **The wrapp store:** 95 catalog wrapps + Add-local + GitHub import (each = a registered manifest).
- **Team Mode — proven multiplayer:** one shared folder, LWW sync, member↔member cursors (teammates as
  MacCats), wrapp *surface control* (open a wrapp on a teammate's screen), git backing, zero-knowledge
  cloud backup/restore, seat cap. Free = host + 3.
- **The presence layer:** the notch (cards, God, dictation), *God's cat* (an ambient companion that
  follows your cursor — resizable, mew, intro, draggable + right-click nap/play/come-to-the-notch).
- **"Everything's a wrapp" — the first visible step:** a WRAPPS list in Settings where Notch · God ·
  Flow · God's cat are each **removable** (off = disabled).
- **The Run layer (early):** routines draft an autonomous company's moves; a human gates every send.

Direction, not yet built (say so, or don't say it):
- Native wrapps as **real catalog entries** (a native manifest kind) — today the catalog only holds
  launchable web wrapps; the WRAPPS list is the bridge.
- **Onboarding = adding your first wrapps** (the cat as the first add). Spec: ONBOARDING-WRAPPS-SPEC.md.
- Agencies' *build-for-clients* lane (multi-tenant / white-label).
- The autonomous rungs of the Run layer.

## 3. The story the product now tells (this is what the landing must perform)

1. **You already pay for an AI.** Switchboard routes it — into everything — without owning you.
2. **Your Switchboard is yours because you assemble it.** Add a wrapp; a capability lights up. Add
   Flow → voice everywhere. Add the cat → presence. Add a teammate → multiplayer, one folder, no login.
3. **Nothing leaves.** The five noes: no account, no second bill, no data to the developer, no context
   handover, no operator listening.
4. **Land solo, invite the team.** The same board becomes your team's board.

## 4. Landing page — what's live vs what's stale

Live now (`thelastprompt.ai/switchboard`): hero **"Bring your own AI"** → patch-bay thesis → setup →
live demo → context-travels → features (privacy · personal · instant) → store → pricing (Free / Pro $10
flat) → how → security → team → devs → FAQ. Design registers: phosphor landing chrome / lime cockpit
product UI. Ordering rules baked in: store before pricing, setup after store.

What no longer matches the direction:
- The hero says *bring your own AI* (the mechanism) but never *assemble your Switchboard from wrapps*
  (the new identity). The assembly + capability-accrual story is absent.
- No **founders + agencies** framing anywhere.
- The **team** section is a mock — Team Mode is now real and provable (roster, cats, one folder).
- **God's cat** / ambient presence — the most memorable, showable thing — isn't on the page.
- The **"everything's a wrapp" WRAPPS list** (a genuinely new idea) isn't shown.
- `#how` ("Operator, patch me through") is now redundant with the patch-bay thesis (flagged before).

## 5. Landing improvements — prioritized, honest

1. **Reframe the hero around assembly, keep BYO-AI as the how.** The patch-bay jacks *are* wrapps: the
   hero interaction becomes *adding a wrapp → a capability lights* (add Flow → the voice jack glows;
   add the cat → it walks onto the board). Line direction (arrange, don't invent): *your AI, routed
   everywhere; your Switchboard, assembled from wrapps.* Keep the five noes right under it.
2. **Replace the team mock with the real thing.** Two Macs, one folder, teammates as cats, a wrapp
   opened on a teammate's screen — it's shipped, so show real captures. "Land solo, invite the team."
3. **Add God's cat as the charm beat** — a short loop of the cat following the cursor / being told to nap.
   It's the product's personality in three seconds, and it's true.
4. **Show the WRAPPS list** as the proof of "everything's a wrapp" — a panel where built-ins are toggles.
5. **A founders + agencies band** (not the hero): who assembles with this, and why — builders.
6. **Make capability accrual visible in the store section:** "adding X gives Y to your whole board."
7. **Trim:** kill `#how` (covered by the patch-bay); keep pricing honest (Pro = team/cloud, no per-seat;
   billing still a contact modal); never say "not built yet" (anti-sell) — say the direction as
   direction, or leave it out.

Guardrails that survive all of the above (relay-privacy-positioning): "never shared with the app's
developer — prompts go only to your own provider"; "no second bill, no API key"; "no account with us or
any app"; third-party sandbox claims carry the "today's catalog is first-party" clause.

## 6. What to build next (in this order)

1. Native-wrapp manifest kind → built-ins become real catalog entries (finishes "everything's a wrapp").
2. Onboarding = adding your first wrapps (the cat as the first add) — the spec exists.
3. Landing v2 per §5 — after 1–2, so the page performs what's real.
4. Agencies' build-for-clients lane; the Run layer's next rungs.
