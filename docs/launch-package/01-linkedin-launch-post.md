# LinkedIn launch post

## Primary post

My feed is full of people building with AI.

In everyday conversations, I meet people who are still figuring out what to do with ChatGPT. Claude Code sounds like something for developers. Most of the apps in my feed never reach them.

I keep thinking about the gap between those two worlds.

Someone builds a useful tool. To try it, you need to clone a repo, install dependencies, find an API key, connect your accounts and explain your project again.

The person who just wants to launch a brand has already left.

That’s why I’m building Switchboard.

It connects lightweight apps to the AI you already use, the tools you’ve connected and the project context you choose to share.

So an app can be small and focused, while the experience is personal to you.

Take building a brand.

Claude Code gives you a powerful coding environment. A brand-building app should give you a place to develop a brief, research the market, compare competitors and make decisions about the brand.

The AI can be the same. The experience should fit the job.

Then you open AdForge to make ads. It can work from the brand context you’ve already built, instead of asking you to start the conversation again.

A logo tool, a website reviewer and an ads analyst can each give you a different way to work with that same project.

Switchboard is the connection between them: your AI compute, your tools and your context, available to the apps you allow.

Today, that includes Claude Code and Codex, with local models for supported tasks such as voice and text processing. There’s an initial setup, and individual apps need permission to use it.

For builders, this opens up a different way to distribute software. Build the useful interface and agent behaviour. Connect it to the user’s setup.

For everyone else, the promise is simpler: find an app for what you need to do, open it and get to work.

I want more of the things we’re building with AI to become things people actually use.

That’s the direction I’m taking Switchboard.

What’s one task you wish had its own app, running on your AI?

## Shorter launch version

My feed is full of people building with AI. Most people I know just want an easier way to get something done.

Between those two groups sits a setup problem: install this, connect that, bring an API key, explain your project again.

I’m building Switchboard to close that gap.

It connects lightweight apps to your existing AI, tools and project context, with access you control.

A brand studio can run on your Claude Code. An ad creator can use the brand brief you already built. A website reviewer can work with the same project. Supported tasks can use local models, too.

The app changes. You don’t have to rebuild your entire AI setup.

For builders, it’s a way to distribute useful, focused software that runs on the user’s setup.

For users, it should feel like opening the right app for the job.

What would you want to use this for?

## Editorial choices

- The opening is a personal observation, not an unsupported claim about global app adoption.
- “Current subscriptions” means supported access through Claude Code or Codex. It does not promise that any subscription can be used by any model client, or that usage is unlimited.
- The shared-context paragraph is supported by AdForge’s existing context/lending integration. A complete filmed cross-app AI run still requires its own verification.
- Keep Crest out of the primary launch claim until a usable capture confirms the current logo experience. It can appear in the video concept and follow-up once verified.
- The post is a draft. Nothing has been posted to LinkedIn.
